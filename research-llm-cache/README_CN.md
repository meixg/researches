# LLM Prompt Caching: 行业对比与技术分析报告 (2026年7月)

## 执行摘要

Prompt Caching（提示词缓存/上下文缓存）已从一种小众的性能优化手段演变为大语言模型（LLM）应用的核心经济驱动力。截至2026年7月，所有主流模型厂商（OpenAI、Anthropic、Google、DeepSeek、阿里巴巴等）均已实现缓存机制，可将输入 Token 成本降低 **50%至98%**，并显著降低首字延迟（TTFT）。

本报告分析了当前前沿模型领域的缓存实现策略、定价模式及技术要求。

## 2. 重点厂商详细解析

### 2.1 OpenAI (GPT-5, GPT-4o 系列)
OpenAI 采用**零配置**方案。系统自动检测 Prompt 中的重复前缀。
- **要求**：Prompt 长度需超过 1,024 tokens。
- **机制**：精确前缀匹配。缓存在整个组织范围内共享。
- **TTL**：非高峰时段通常保留 1 小时，但在高负载下可能会提前释放。

### 2.2 Anthropic (Claude 4, Claude 3.5 系列)
Anthropic 率先推出了**显式控制**模型，通过 `cache_control` 参数赋予开发者精细控制权。
- **实现**：开发者在消息数组或系统提示词中插入标记。
- **定价**：首次处理（写入）加收 25% 费用，但后续读取可享受 10% 的极低折扣。
- **TTL**：默认为 5 分钟。支付更高写入费用可获得 1 小时 TTL。

### 2.3 DeepSeek (V4, V3)
DeepSeek 提供了行业内最具**攻击性且高效**的缓存方案。
- **粒度**：支持小至 64 tokens 的前缀匹配。
- **成本**：命中价格极低（如 Flash 模型仅 $0.0028/1M tokens），在长对话和智能体（Agent）循环中极具优势。

### 2.4 Google Gemini (2.5, 1.5 Pro & Flash)
Google 提供混合模式：
- **隐式缓存**：新版本模型自动提供 75% 折扣。
- **显式缓存**：允许创建 `cachedContent` 对象，按**存储时长**（$/M tokens/小时）计费。适合在数小时内频繁查询的大型静态上下文。

## 3. 最佳实践建议

为了最大化缓存命中率并降低成本，建议遵循以下架构模式：

1.  **静态在前，动态在后**：始终将静态内容（系统指令、工具定义、Few-shot 示例）放在 Prompt 的最开头。
2.  **避免微小变动**：不要在系统提示词或早期的消息块中包含“当前时间”或“用户 ID”等动态数据，请将它们放在最后。
3.  **对齐 Token 阈值**：注意厂商的最小触发阈值（通常为 1,024）。过短的 Prompt 无法享受缓存收益。
4.  **监控用量**：始终记录 API 响应中的 `cached_tokens` 字段，以验证优化策略的有效性。

---

## 4. 结论

LLM 缓存已分化为两种体验：以 OpenAI/DeepSeek 为代表的**自动模式**（追求易用性）和以 Anthropic/Gemini 为代表的**显式模式**（追求极致优化）。对于 2026 年的生产级应用，Prompt 缓存已不再是可选项，而是维持竞争力的核心技术手段。
