Detailed Analysis

1. The "Set and Forget" Group (OpenAI, DeepSeek, GLM)

These providers focus on developer experience by automatically identifying repeating prefixes. DeepSeek stands out with its 64-token granularity, making caching effective even for shorter conversations. OpenAI requires at least 1,024 tokens, making it most suitable for long system prompts or RAG contexts.

2. The "Granular Control" Group (Anthropic, Mistral)

Anthropic requires developers to explicitly mark content blocks with cache_control. While this adds development overhead, the 90% discount is industry-leading for frontier models. Mistral uses a prompt_cache_key to group similar requests together.

3. The "Storage" Model (Google Gemini, Doubao)

Gemini's explicit caching is unique because it bills for storage time ($/M tokens/hr). This makes it highly predictable for stable, massive datasets (like entire code repositories) that are queried frequently over a fixed window. Doubao recently adopted a similar hourly storage billing model.

Best Practices for 2026

  • Stable Prefixing: Ensure the first part of your prompt is identical across requests. Even a single extra newline will break the cache.
  • Dynamic Tail: Move all volatile information (timestamps, unique session IDs, the actual user question) to the end of the message array.
  • Monitor Usage: Always log the cached_tokens field from the API response to verify your optimization strategy is working.
